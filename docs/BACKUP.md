# バックアップと復旧の手順

個人間の売買を扱うため、消えて困るのは **取引の記録**(誰が誰に何をいくらで売ったか)と
**利用者の情報**。画像は再アップロードで戻せるが、取引の記録は戻せない。

対象は3つ。

| 対象 | 中身 | 消えたときの影響 |
|---|---|---|
| データベース | 会員・出品・取引・メッセージ・評価・監査ログ | 復旧不能。最優先で守る |
| Storage(画像) | 商品画像・プロフィール画像 | 出品の見栄えが崩れる。出品者に再アップロードを依頼すれば戻る |
| 環境変数 | 各サービスの鍵 | 各サービスの管理画面から再発行できる |

---

## 1. Supabase の自動バックアップを確認する

Supabase ダッシュボードの **Database → Backups** を開く。

- 取得の頻度と保持期間は**契約プランによって変わる**(無料プランでは
  自動バックアップが無い、または保持期間が短い)。実際の表示を見て、
  **いつの時点まで戻せるのか**を確認する。
- 日次バックアップでは「今日の午前中の取引」は戻せない。取引の件数が増えてきたら、
  任意の時点に戻せる仕組み(Point-in-Time Recovery)の有無をプラン表で確認する。

**ここで確認した内容(頻度・保持期間・PITR の有無)を、この文書の最後に書き足しておく。**

---

## 2. 手元にコピーを取る(月1回、および大きな変更の前)

Supabase 側の自動バックアップとは別に、手元にも1本持っておく。
プロジェクトごと消えた場合に効くのはこちら。

```bash
# 接続文字列は Supabase の Settings → Database → Connection string から取る
# パスワードを含むため、履歴に残さない(先頭に空白を入れるか、環境変数から渡す)
pnpm supabase db dump --db-url "$SUPABASE_DB_URL" -f backup-$(date +%Y%m%d).sql
pnpm supabase db dump --db-url "$SUPABASE_DB_URL" --data-only --use-copy -f data-$(date +%Y%m%d).sql
```

- 1本目がスキーマ、2本目がデータ。復旧にはこの2本を使う。
- 出力には**会員の個人情報が入る**。暗号化されたディスクか、権限を絞った
  クラウドストレージに置く。チャットやメールには添付しない。
- 画像は Supabase ダッシュボードの **Storage** から
  バケットごとダウンロードできる(件数が多い場合は CLI か API を使う)。

## 3. 復旧の手順

### 3-1. 一部のデータを間違って消した場合

1. まず**書き込みを止める**。Vercel でメンテナンス用の環境変数を立てるか、
   デプロイを一時停止する(操作を続けさせると、戻す先が動き続けてしまう)。
2. Supabase の **Database → Backups** から、消す前の時点を選んで復元する。
3. 復元後、`/admin` のダッシュボードで整合性の警告が出ていないか確認する
   (取引と商品の状態のズレは自動検知される)。

### 3-2. プロジェクトごと失った場合

1. 新しい Supabase プロジェクトを作る。
2. `supabase/setup-hosted.sql` を SQL Editor に貼って実行する(スキーマと初期データ)。
3. 手元のバックアップからデータを戻す。

   ```bash
   psql "$NEW_DB_URL" -f data-YYYYMMDD.sql
   ```

4. **Authentication の設定をやり直す**(Site URL / Redirect URLs / メールテンプレート)。
   会員のログイン情報は `auth` スキーマにあるため、データの復元に含まれる。
5. Vercel の環境変数(`NEXT_PUBLIC_SUPABASE_URL` / 各種キー)を新しいプロジェクトのものに
   差し替えて再デプロイする。
6. Storage のバケット(`listing-images` / `avatars`)を作り直し、画像を戻す。
7. 決済は Stripe 側に記録が残っている。アプリの取引記録と突き合わせ、
   食い違いがあれば Stripe ダッシュボードを正とする。

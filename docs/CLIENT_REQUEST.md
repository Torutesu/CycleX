## A. 文面(🔴 法的前提)

掲載枠は実装済み。**文面をいただければ差し込むだけ**で、こちらの追加作業は数十分。

| #   | もの                     | 掲載先       | 形式                                  |
| --- | ------------------------ | ------------ | ------------------------------------- |
| A-1 | 特定商取引法に基づく表記 | `/tokushoho` | テキスト / Word / Google ドキュメント |
| A-2 | 利用規約                 | `/terms`     | 同上                                  |
| A-3 | プライバシーポリシー     | `/privacy`   | 同上                                  |

現在は 3 ページとも「現在準備中です」と表示されます。
**特商法表記は販売を行う前提として法律上必須**なので、A-1 が無い状態で
一般公開はできません(関係者限定の検証公開は可)。

A-1 に最低限必要な項目(こちらで様式は用意できますが、値は甲にしか出せません):

- 販売業者の名称 / 所在地 / 電話番号 / 代表者名
- 問い合わせ先メールアドレス(下記 B-1 と同じで可)
- 販売価格・手数料の表示方法、支払方法・支払時期
- 引渡し時期、返品・キャンセルの可否と条件

## B. 連絡先・ドメイン(🔴)

| #   | もの                             | 用途                                                     | 無いとどうなるか                                             |
| --- | -------------------------------- | -------------------------------------------------------- | ------------------------------------------------------------ |
| B-1 | **問い合わせ窓口**               | 利用停止画面・購入完了画面・特商法表記からの導線         | 「運営までお問い合わせください」と書いてあるのに連絡先が無い |
| B-2 | **本番ドメイン**(例 `cyclex.jp`) | サイト本体の URL、メール本文中のリンク、OGP              | 公開できない                                                 |
| B-3 | **DNS の管理権限**               | Vercel のドメイン設定、Resend の SPF / DKIM レコード追加 | 独自ドメインでのメール送信ができない                         |

B-1 はメールアドレス・問い合わせフォームの URL・どちらでも構いません。
いただいた時点でこちらが画面に導線を入れます(現在は文言のみでリンクがありません)。

B-3 は「レコードを 3〜4 件追加する」だけです。甲側で作業いただくか、
値をこちらがお渡しして追加していただくか、管理画面の権限をいただくかのいずれかで。

## C. 運用アカウント(🔴 / 名義は甲)

サービスの継続運営に関わるため、**すべて甲名義で作成**していただくのが原則です
(乙名義だと契約終了時に引き継げません)。作成手順はこちらでご案内できます。

| #   | サービス         | いただくもの                                                 | 備考                                                               |
| --- | ---------------- | ------------------------------------------------------------ | ------------------------------------------------------------------ |
| C-1 | **Supabase**     | プロジェクト(Tokyo リージョン)への招待、または API キー 3 種 | DB・認証・画像保管。無料枠で開始可                                 |
| C-2 | **Vercel**       | プロジェクトへの招待                                         | アプリの実行環境。無料枠で開始可                                   |
| C-3 | **Resend**       | API キー + 送信元アドレス(`EMAIL_FROM`)                      | 🔴 メール送信。無料枠あり(通数は申込時にご確認ください)            |
| C-4 | **Google Cloud** | OAuth クライアント ID / シークレット                         | 🟡 「Google で続ける」のログイン。未設定ならボタン自体が出ません   |
| C-5 | **Sentry**       | DSN(1 行の URL)                                              | 🟡 障害の通知。無料枠は月 5,000 件。無いと障害がログにしか残らない |

`EMAIL_FROM` は `CycleX <noreply@(B-2 のドメイン)>` の形式でお願いします。
このアドレス宛の返信は誰も読まないため、返信を受ける窓口は B-1 で別途必要です。

C-4 は後回しにしても画面は壊れません。Supabase 側で Google を有効にするまでは
ログイン・会員登録画面にボタンを出さない実装になっています。

## D. 決済(⚪ 後回し可)

| #   | もの                                     | 備考                                                       |
| --- | ---------------------------------------- | ---------------------------------------------------------- |
| D-1 | **Stripe アカウント**(甲名義)            | 本人確認・入金先口座の登録が必要。審査に数日かかることあり |
| D-2 | 本番 API キー / Webhook 署名シークレット | D-1 完了後に発行                                           |
| D-3 | **販売手数料率**の確定                   | 現在の設定は 7%。画面表示にのみ使用(精算処理は対象外)      |

Stripe が揃うまでは `CYCLEX_PAYMENTS_DISABLED=1` を入れて、
**購入導線だけを閉じた状態**で公開できます。閲覧・会員登録・出品・メッセージ・
評価・管理画面はすべて動きます。キーが揃った時点でフラグを外すだけで開通します。

> 売上金の出品者への送金・返金処理は別紙1 第3項により対象外です。
> 返金が必要な取引は管理画面に一覧され、甲が Stripe ダッシュボードで返金したあと
> 管理画面で消し込む運用になります。

3. C-3 Resend の API キーと `EMAIL_FROM`(+ B-3 の DNS 設定)

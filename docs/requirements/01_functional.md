# 01. 機能要件

各機能を FR-XX で採番する。優先度は MVP 内での実装順序の目安(Must = 検証に必須 / Should = MVP 内で実装するが簡易で可)。

---

## FR-01 会員登録・認証

優先度: Must

### FR-01-1 メール/パスワード登録

- 入力項目: メールアドレス、パスワード、表示名
- パスワード要件: 8 文字以上、英字・数字を各 1 文字以上含む
- 登録時にメールアドレス確認(確認リンク付きメール送信)。確認完了までは購入・出品・メッセージ不可(閲覧は可)
- メールアドレスは全ユーザーで一意
- 登録完了時にウェルカムメールを送信(FR-13)

### FR-01-2 ソーシャルログイン(1 種)

- **Google ログイン**(OAuth 2.0 / OIDC)を採用
- 初回 Google ログイン時にアカウントを自動作成(表示名は Google プロフィール名を初期値とする)
- 同一メールアドレスの既存メール/パスワードアカウントが存在する場合はアカウントを統合(同一ユーザーとしてログイン)

### FR-01-3 ログイン/ログアウト

- メール+パスワード、または Google でログイン
- セッションは Cookie ベース(Secure / SameSite=Lax)。有効期限はリフレッシュ込みで 30 日程度
  - **実装との差分(要確認)**: 採用した Supabase Auth(`@supabase/ssr`)の Cookie は既定で `HttpOnly` ではない。
    ブラウザから Storage へ画像を直接アップロードするために JavaScript からセッションを読む必要があるため。
    HttpOnly を必須とする場合は、画像アップロードをすべてサーバー経由に変更する追加実装が必要。
  - **実装との差分(要確認)**: 有効期限 30 日の上限設定(Session timebox)は Supabase の有料プラン機能。
    Free プランでは無期限になる。設定項目は README「本番 Supabase の設定項目一覧」を参照。
- ログイン失敗時は「メールアドレスまたはパスワードが正しくありません」と表示(存在有無を特定させない)

### FR-01-4 パスワードリセット

- 登録メールアドレス宛にリセットリンク(有効期限 1 時間、1 回限り)を送信
- リンクから新パスワードを設定。未登録メールアドレスでも「送信しました」と同一表示にする

### FR-01-5 退会

- 設定画面から退会可能。確認ダイアログで注意事項(復元不可・進行中取引がある場合は不可)を表示
- **進行中の取引(購入申込〜完了前)がある場合は退会不可**とし、理由を表示
- 退会は論理削除: 個人プロフィールは匿名化(表示名を「退会済みユーザー」に置換、アイコン・自己紹介削除)、公開中の商品は自動で取下げ、取引履歴・評価・メッセージはデータとして保持
- 退会後は同一メールアドレスで再登録可能(新規アカウントとして扱う)

### FR-01-6 認可(アクセス制御)

| 操作                                      | ゲスト | 一般会員 | 管理者 |
| ----------------------------------------- | ------ | -------- | ------ |
| 検索・一覧・商品詳細閲覧                  | ○      | ○        | ○      |
| お気に入り/出品/購入/メッセージ/評価/通報 | ×      | ○        | ○      |
| 管理画面                                  | ×      | ×        | ○      |

- 未ログインで要ログイン操作を行った場合はログイン画面へ誘導し、ログイン後に元の操作へ復帰する

## FR-02 プロフィール

優先度: Must

### 項目

| 項目             | 必須 | 制約                                                                            |
| ---------------- | ---- | ------------------------------------------------------------------------------- |
| 表示名           | ○    | 1〜30 文字                                                                      |
| アイコン画像     | −    | JPEG/PNG/WebP、5MB 以下、正方形にクロップして保存。未設定時はデフォルトアイコン |

- 本人による編集画面(即時反映)
- 公開プロフィールページ: 表示名・アイコン・自己紹介・所在地・評価サマリー(平均★と件数)・出品中の商品一覧・受け取った評価一覧を表示
- メールアドレス・パスワードの変更は設定画面から(メール変更時は新アドレスの確認メールを送信)

### FR-03-2 状態管理

| 状態               | 説明                                                                                |
| ------------------ | ----------------------------------------------------------------------------------- |
| 下書き (draft)     | 保存時の必須チェックなし(タイトルのみ必須)。本人のみ閲覧可。件数上限 20 件          |
| 公開中 (published) | 全項目バリデーション後に公開。検索・一覧に表示                                      |
| 取引中 (trading)   | 購入申込〜取引完了の間。新規購入不可。一覧では「取引中」表示                        |
| 売却済 (sold)      | 取引完了後。詳細は閲覧可・「SOLD」表示                                              |
| 取下げ (withdrawn) | 出品者が非公開化。本人のみ閲覧可。再公開可能                                        |
| 非表示 (suspended) | 管理者による非表示(FR-11)。本人には「運営により非公開」と表示。本人による再公開不可 |

- 公開・取下げ・編集は出品者本人のみ。**取引中・売却済の商品は編集・取下げ不可**
- 公開中の商品の編集は即時反映

## FR-04 検索・一覧

優先度: Must

### FR-04-1 キーワード検索

- 対象フィールド: タイトル、商品説明、ブランド名、モデル名
- スペース区切りで AND 検索。PostgreSQL の全文検索+trigram(pg_trgm)による部分一致で実装
- 対象は「公開中」および「取引中」の商品(売却済はデフォルト非表示、絞り込みで表示可)

### FR-04-2 絞り込み(組み合わせ可)

| 条件              | UI                                                                         |
| ----------------- | -------------------------------------------------------------------------- |
| カテゴリ          | 単一選択(パーツはサブカテゴリも指定可)                                     |
| ブランド          | 複数選択                                                                   |
| 価格帯            | 下限・上限の入力(プリセット: 〜1万 / 1〜3万 / 3〜10万 / 10〜30万 / 30万〜) |
| フレームサイズ    | 複数選択(XS〜XL)                                                           |
| 地域(発送元/受渡) | 都道府県の複数選択                                                         |
| コンディション    | 複数選択                                                                   |
| 販売状況          | 販売中のみ / 売却済含む(デフォルト: 販売中のみ)                            |

- スマホではボトムシート型フィルタパネル、PC ではサイドバーに表示
- 適用中の条件はチップ表示し、個別解除・全解除が可能

### FR-04-3 並び替え

- 新着順(デフォルト)/ 価格の安い順 / 価格の高い順 / お気に入りの多い順

### FR-04-4 ページネーション

- 1 ページ 24 件。スマホは「もっと見る」ボタンによる追加読み込み、PC はページ番号式(両者とも URL クエリで状態を保持し、共有・ブラウザバックに対応)
- 検索条件・並び替え・ページはすべて URL クエリパラメータで表現する

### FR-04-5 一覧カード表示

- サムネイル、タイトル、価格、カテゴリ、フレームサイズ(車体のみ)、地域、お気に入りボタン、取引中/SOLD バッジ
- グリッド: スマホ 2 列、タブレット 3 列、PC 4 列

## FR-05 商品詳細

優先度: Must

- **画像スライダー**: スワイプ対応(スマホ)+サムネイルストリップ/矢印(PC)。タップで全画面表示、枚数インジケータ付き
- **スペック表示**: カテゴリ/ブランド/モデル名/年式/フレームサイズ/コンポーネント/走行距離目安/コンディション/受渡方法/地域を定義リスト(表)で表示。未入力項目は非表示
- 価格・商品説明・出品日時・更新日時
- **出品者情報**: アイコン・表示名・所在地・評価サマリー(平均★・件数)。タップで公開プロフィールへ
- アクション:
  - 購入者視点: 「購入手続きへ」(FR-08)、「お気に入り」(FR-06)、「出品者に質問」(FR-07)、「通報」(FR-11)
  - 出品者本人視点: 「編集」「取下げ/再公開」
  - 状態別: 取引中は購入ボタンを「取引中」表示で無効化、売却済は「SOLD」表示
- 同一出品者のその他の公開中商品を最大 6 件表示

## FR-06 お気に入り

優先度: Must

- 商品カード・商品詳細のハートボタンで登録/解除(ログイン必須、非同期で即時反映)
- 商品ごとのお気に入り件数を詳細画面に表示
- マイページ「お気に入り一覧」: 登録日時の新しい順、ページネーションあり。売却済・取下げ・非表示になった商品はその旨表示
- 自分の出品にはお気に入り不可

## FR-07 メッセージ

優先度: Must

- **商品単位**の出品者・購入希望者間 1 対 1 テキストメッセージ(スレッド = 商品 × 購入希望者の組)
- 商品詳細の「出品者に質問」から開始。取引成立後も同一スレッドで取引連絡を継続
- テキストのみ(1〜1,000 文字)。画像添付・既読表示・リアルタイム同期は対象外(画面表示時+手動更新で取得)
- メッセージ一覧画面: 自分が参加するスレッドを最終メッセージ日時降順で表示。未読件数バッジ表示(ヘッダーにも合計未読バッジ)
- 新着メッセージはメール通知(FR-13。連続送信の抑制のため同一スレッドで一定時間内は再通知しない)
- 退会・非表示ユーザーとのスレッドは閲覧のみ可(新規送信不可)。
  運営が非表示にした商品のスレッドも同様に新規送信不可とする(質問の開始を塞ぐのと対称)

## FR-08 取引フロー

優先度: Must

### ステータス遷移

```
[公開中]
   │ 購入者が「購入手続きへ」→ 決済(FR-09)
   ▼
(1) 支払い済み paid ──────────── 商品: 取引中
   │ 出品者が「発送しました/受渡準備完了」を実行(任意で追跡番号・受渡場所等の連絡欄)
   ▼
(2) 発送・受渡連絡済み shipped
   │ 購入者が「受け取りました」を実行
   ▼
(3) 受取確認済み received
   │ 双方の評価完了(FR-10)※どちらか一方でも評価すれば相手に評価依頼を通知
   ▼
(4) 取引完了 completed ───────── 商品: 売却済
```

### 要件

- 購入確定(決済完了)時点で商品を「取引中」にし、**他ユーザーの購入操作を排他制御**(決済セッション開始〜完了の間も二重購入を防止する)
- 取引画面: 現在のステータス、次に行うべきアクション、取引相手、商品概要、メッセージスレッドへの導線をワンページで表示
- 各ステータス変更時に相手方へメール通知(FR-13)
- 発送連絡時の入力: 連絡メモ(任意、500 文字以内。追跡番号や対面受渡の待ち合わせ情報を想定)。配送業者 API 連携は対象外
- **キャンセル**: 当事者間での自動キャンセル機能は設けない。トラブル時は管理者が管理画面から取引をキャンセル状態に変更できる(返金操作自体は Stripe ダッシュボードで運営が実施し、システムはステータス変更と記録のみ)
- **停滞取引の扱い**(運用補助として追加): 支払いから 7 日たっても発送連絡が無い場合は出品者へ、
  発送連絡から 14 日たっても受取確認が無い場合は購入者へ、日次で催促メールを送る(同一取引には 7 日に 1 回まで)。
  それでも動かない取引は、管理者が管理画面から受取確認・取引完了を代理で実行できる
- 取引履歴: マイページに「購入した取引」「出品した商品の取引」を一覧表示(進行中/完了/キャンセルのタブ)

## FR-09 決済

優先度: Must

- 決済代行: **Stripe**(1 社)。標準機能の範囲内で **Stripe Checkout(ホスト型決済ページ)** によるクレジットカード決済(Visa / Mastercard / AMEX / JCB は Stripe の対応範囲に準ずる)
- フロー:
  1. 購入者が「購入手続きへ」→ 確認画面(商品・価格・受渡方法)→「支払いへ進む」
  2. サーバーで Checkout Session を作成し Stripe へリダイレクト
  3. 決済完了は **Webhook(checkout.session.completed)** で確定し、取引を paid へ遷移・商品を取引中へ(成功画面への戻りだけでは確定しない)
  4. 決済失敗・離脱時は取引を成立させず商品を公開中に戻す(Checkout Session の有効期限 **45 分**)
     - **実装との差分(要確認)**: Stripe は `expires_at` に「現在より 30 分以上先」を要求するため、
       ちょうど 30 分だと時刻のわずかなずれで Checkout の作成そのものが失敗する。45 分に変更した。
     - 決済画面から戻った場合は、その場で取引をキャンセルして商品を購入可能に戻す(45 分待たない)
- 金額は商品価格(送料込み・税込)。**カード情報は自システムで保持しない**(PCI DSS 対応は Stripe に委譲)
- 返金・売上金の出品者送金・分割送金(Connect 等)・エスクローは対象外(運営がシステム外で対応)
- Stripe の決済 ID(session/payment_intent)を取引レコードに記録し、管理画面から参照可能にする

## FR-10 評価

優先度: Must

- 受取確認(received)後、**取引の両当事者が相互に 1 回ずつ**評価を登録できる
- 内容: 5 段階(★1〜5)必須+コメント(任意、500 文字以内)
- 相手の評価は**双方の評価完了まで(または一方の評価から 14 日経過まで)非公開**とし、報復評価を抑止する。条件成立時に双方公開し取引を completed へ
- 一度登録した評価の編集・削除は不可(管理者は非表示化可能)
- 公開プロフィールに平均★(小数 1 桁)・件数・評価一覧(評価者・★・コメント・日時)を表示

## FR-11 通報・非表示

優先度: Must

### 通報(一般会員)

- 対象: 商品、ユーザー
- 入力: 理由区分(禁止出品物 / 詐欺の疑い / 不適切な内容 / 規約違反 / その他)+詳細(任意、1,000 文字以内)
- 同一ユーザーによる同一対象への通報は 1 回まで。通報者情報は被通報者に開示しない

### 非表示化(管理者)

- 管理画面から商品・ユーザーを非表示化/解除できる(理由メモを記録)
- 商品の非表示: 検索・一覧・詳細から除外。出品者には「運営により非公開」表示
- ユーザーの非表示(利用停止): 当該ユーザーはログイン時に利用停止画面のみ表示され全機能利用不可。公開中の商品はすべて非表示化。進行中取引がある場合は管理者に警告表示
- 通報一覧: ステータス(未対応 / 対応済み)で管理し、通報から対象の詳細・非表示操作へ遷移できる

---

## FR-12 管理画面

優先度: Must

- 管理者ロールのみアクセス可能(`/admin` 配下、一般 UI とは独立したレイアウト)
- **利用者管理**: 一覧(検索: 表示名・メール、絞り込み: 状態)、詳細(プロフィール・出品・取引・評価・通報履歴)、非表示化/解除
- **出品管理**: 一覧(検索: キーワード、絞り込み: カテゴリ・状態)、詳細、非表示化/解除
- **取引管理**: 一覧(検索: 商品名・当事者、絞り込み: ステータス・期間)、詳細(Stripe 決済 ID 含む)、キャンセル状態への変更
- **通報管理**: FR-11 の通報一覧・対応
- **ブランドマスタ管理**: 追加・名称変更・無効化
- **簡易ダッシュボード**: 会員数・出品数・取引数・流通総額(GMV)の累計と直近 30 日推移(日次グラフ)、直近の通報・取引の一覧
- 管理者アカウントはシード(環境変数/DB 直接投入)で作成。管理画面上での管理者追加 UI は対象外

---

## FR-13 メール通知

優先度: Must

| #   | イベント                               | 宛先             |
| --- | -------------------------------------- | ---------------- |
| 1   | 会員登録(メールアドレス確認)           | 本人             |
| 2   | 登録完了(ウェルカム)                   | 本人             |
| 3   | パスワードリセット                     | 本人             |
| 4   | メールアドレス変更確認                 | 本人(新アドレス) |
| 5   | 商品が購入された(決済完了)             | 出品者           |
| 6   | 購入完了(決済完了)                     | 購入者           |
| 7   | 発送・受渡連絡があった                 | 購入者           |
| 8   | 受取確認があった                       | 出品者           |
| 9   | 評価が届いた/評価依頼                  | 相手方           |
| 10  | 取引完了                               | 双方             |
| 11  | 取引がキャンセルされた(管理者操作)     | 双方             |
| 12  | 新着メッセージ(スレッドごとに抑制付き) | 受信者           |

- 送信はトランザクションメール SaaS(Resend)経由。テキスト主体+最小限の HTML テンプレート
- 5〜12 は設定画面で通知カテゴリごとに ON/OFF 可能(1〜4 の認証系はオフ不可)
- 配信失敗はログに記録(再送の自動化は対象外)

## FR-14 デザイン

優先度: Must

- 既製 UI コンポーネントライブラリ(**shadcn/ui + Tailwind CSS**)を基礎とした標準的な画面実装
- **スマホファースト**: 375px(iPhone 基準)を基準にデザインし、ブレークポイント sm(640)/ md(768)/ lg(1024)/ xl(1280)で PC レイアウトへ展開
- スマホは下部固定タブバー(ホーム / 検索 / 出品 / メッセージ / マイページ)、PC はヘッダーナビゲーション
- ロゴ・ブランドアイデンティティの制作は対象外(テキストロゴ+既製アイコンセットで代替)
- 詳細は [02_screens.md](02_screens.md) を参照

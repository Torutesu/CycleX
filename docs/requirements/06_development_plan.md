## 3. 受入基準(主要シナリオ)

以下のシナリオが検証環境(Stripe テストモード)で完了することをもって受入とする。

1. **会員登録**: メール登録 → 確認メール → ログイン / Google ログイン / パスワードリセット / 退会
2. **出品**: 画像 10 枚+全項目で下書き保存 → 公開 → 編集 → 取下げ → 再公開
3. **探す**: キーワード+カテゴリ+ブランド+価格帯+サイズ+地域で絞り込み、並び替え・ページ送り、スマホ幅(375px)と PC 幅(1280px)で崩れなし
4. **商品詳細**: スライダー操作、スペック表、出品者プロフィール遷移
5. **お気に入り**: 登録/解除、一覧表示
6. **メッセージ**: 購入前質問の送受信、未読バッジ、メール通知
7. **取引**: 購入申込 → テストカード決済 → paid → 発送連絡 → 受取確認 → 相互評価 → 完了(各ステップで相手にメール通知、二重購入が防止されること)
8. **評価**: 双方評価後に公開、プロフィールに平均★反映
9. **通報・非表示**: 通報 → 管理画面で確認 → 商品/ユーザーの非表示化 → 一般画面から消えること
10. **管理画面**: 利用者・出品・取引の一覧/検索、ダッシュボード数値表示、取引キャンセル操作
11. **メール通知**: FR-13 の全イベントで送信、設定画面での ON/OFF が反映

## 4. 前提・甲側の準備事項

- ドメイン、および各 SaaS アカウント(Vercel / Supabase / Stripe / Resend / Google Cloud)の甲名義での用意(構築・設定は乙)
- 利用規約・プライバシーポリシー・特商法表記の文面支給(掲載枠は乙が実装)
- 販売手数料率など事業パラメータの決定
- 各マイルストーンでのフィードバック(1 週間以内目安)

## 5. リスクと対応方針

| リスク | 対応 |
|---|---|
| スコープ膨張(機能追加要望) | 別紙1 第3項に基づき対象外を明確化。追加は別途見積り |
| Stripe 審査・アカウント制約 | 検証はテストモードで先行し、本番切替は甲の Stripe 審査完了後 |
| 画像起因のパフォーマンス | アップロード時リサイズ+サムネイル配信で担保 |
| 決済と在庫の競合(二重購入) | DB 部分ユニーク制約+Webhook 確定で担保(FR-08/09) |
| 工数超過 | 各フェーズ終了時に残工数をレビューし、Should 項目(検索の一部絞り込み条件、ダッシュボードのグラフ等)から簡略化を協議 |
